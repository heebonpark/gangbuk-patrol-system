01

소개

이 시스템이 무엇이고, 왜 지금 이 형태로 존재하는가.

PatrolOps는 경비지도사 순회감독 일정과 지사별 근무표(근태 로스터)를 하나의 화면에서 관리하는 웹 애플리케이션입니다. 지사마다 따로 관리되던 엑셀·수기 근무표를 대체하고, 패턴 기반 자동 근무표 생성, 근무시간 자동 집계, 전자서명, 경찰서 제출용 서식 자동생성까지 하나의 도구에서 처리합니다.

현재는 별도 서버 없이 정적 웹페이지 한 장으로 동작하며, 데이터는 이 브라우저(또는 연결한 GitHub 저장소)에 저장됩니다. 이런 구조 덕분에 별도 인프라 투자 없이 아이디어를 빠르게 검증할 수 있었고, 실제로 17개 지사·156명 규모의 시범 데이터로 전체 기능이 동작하는 것을 확인했습니다. 다만 이 구조는 한 조직의 파일럿에 적합한 형태이지, 여러 조직에 판매하는 상용 소프트웨어의 형태는 아닙니다 — 그 격차를 좁히는 계획이 05장 로드맵입니다.

패턴 기반 근무표
근무 패턴 1회 설정 후 달이 바뀌어도 자동으로 이어짐. 연차·병가 등 예외만 그때그때 입력.
근무시간 자동 집계
근태유형별 시간표(일근 8h·석근 14h 등)를 기준으로 월 합계를 자동 계산, 기준 초과 시 경고.
전자서명
근무자가 화면에서 직접 서명하여 종이 결재 없이 근무표 확인 절차를 완결.
근무표 확정 · 수정요청
지사가 근무표를 확정하면 임의 수정이 막히고, 이후 변경은 관리자 승인 절차를 거침.
지사·구역·사번별 접근 제한
지사 단위뿐 아니라 구역(호수)·사번 단위로도 별도 비밀번호를 두어 좁은 범위로 로그인 가능.
경찰서 제출 서식 자동화
순회 일정 데이터로 별지1 서식을 자동 생성해 수기 작성 시간을 제거.
기존 엑셀 근무표 가져오기
지사마다 다르던 엑셀 근무계획표를 업로드하면 헤더 위치를 지정해 그대로 인식·이관.
연차·교육·청원 사전 등록
앞으로 예정된 연차·교육 등을 미리 등록해두면 해당 월 근무표에 자동으로 반영.
근로시간 검증시트 · ERP 연동
91일(13주) 단위 주64h·분기평균52h 초과 여부를 자동 점검하고, ERP 업로드용 양식까지 생성.

상용 자산화까지 로드맵 단계

문제. 지사가 늘어날수록 근무표는 엑셀·수기·구두 확인이 섞인 방식으로 관리되어 왔습니다. 지사별로 서식이 다르고, 초과근무 여부를 사람이 직접 합산해야 하며, 근무자 확인 서명은 종이로 회수·보관됩니다. 지사 수가 늘어날수록 이 관리 부담과 오류 가능성은 선형이 아니라 더 빠르게 증가합니다.

해결. PatrolOps는 근무표 작성·집계·서명·결재·제출서식까지 한 화면에서 처리하도록 지사 단위로 이미 검증했습니다. 나머지는 이 도구를 조직 표준으로 넓히는 문제입니다.

현재 상태. 정식 도입 전 프로토타입 단계입니다. 실사용 데이터 없이 만든 마스킹 샘플로 기능을 검증했으며, 실제 인사·급여 데이터를 넣기 전에 03·06장에 정리한 보안·백엔드 격차를 먼저 해소해야 합니다.

결정 요청. 05장 로드맵의 Phase 1(지사 1~2곳 파일럿, 1~2개월)을 우선 승인하고, 파일럿 결과를 근거로 Phase 2 이후(백엔드 전환) 투자 여부를 다시 검토하는 단계적 접근을 제안합니다.

03

기대효과 — 전사 1,000명 규모 적용 시

아래 수치는 검증된 실적이 아니라, 조직 규모를 대입한 가정 기반 추정입니다. 실제 인건비·소요시간 데이터로 재계산이 필요합니다.

가정 아래 계산의 전제

직원 1,000명 · 지사 40개(지사당 평균 25명) · 지사별 근무표 담당자 40명 · 본사 총괄 관리자 2명 · 관리직 평균 시급 15,000원으로 가정. 지사 담당자는 현재 근무표 작성·확인·결재 준비에 월 6시간을 쓰고, 자동 패턴·전자서명·자동 출력 도입 시 이 중 40%를 절감한다고 가정. 본사는 초과근무 대사(엑셀 수기 합산)에 월 8시간을 쓰고, 자동 경고 기능으로 50%를 절감한다고 가정.

근로기준법 리스크 조기 발견
초과근무 경고가 실시간으로 뜨므로, 월말 정산 후가 아니라 발생 시점에 조정 가능.
결재 리드타임 단축
종이 서명 회수·재발송 없이 즉시 전자서명 완료 → 지사 간 편차 없이 월 마감 표준화.
데이터 일관성
지사마다 다르던 엑셀 서식이 하나로 통일되어, 본사 취합·대사 작업 자체가 줄어듦.
감사·제출 대응 속도
경찰서 제출용 별지1을 자동 생성해 담당자별 수기 작성 편차와 누락을 제거.
04

운영 매뉴얼

지사 담당자와 관리자가 실제로 따라 할 수 있는 절차.

지사 담당자

  1. 01
    로그인
    접속 후 지사 드롭다운에서 소속 지사를 선택하고 비밀번호를 입력합니다. 필요하면 구역(선택) 드롭다운으로 특정 구역/호수만 보이는 좁은 범위로도 로그인할 수 있습니다. 로그인하면 근무표 관리 화면만 표시되며, 다른 지사 데이터는 보이지 않습니다.
  2. 02
    근무표 확인
    각 직원 행의 날짜별 칸은 기본적으로 자동(패턴 기반) 상태입니다. 연차·병가 등 예외가 있는 날짜만 드롭다운에서 직접 코드를 선택하면 자동으로 주황 배경으로 표시되어 구분됩니다.
  3. 03
    근무 패턴 설정
    신규 직원이나 패턴이 바뀐 직원은 이름 아래 프리셋 버튼(야시작 · 주시작 · 상시 · 주주야휴숙숙)을 눌러 반복 패턴을 한 번에 지정합니다.
  4. 04
    엑셀 가져오기 · 사전 등록
    기존에 쓰던 엑셀 근무계획표는 엑셀 가져오기 탭에서 헤더 위치를 지정해 그대로 불러올 수 있습니다. 앞으로 예정된 연차·교육·청원은 관리자 설정 탭에서 기간을 지정해 미리 등록해두면 해당 월이 되었을 때 자동으로 반영됩니다.
  5. 05
    미리보기 · 출력
    미리보기로 범례·서명란·근무시간 합계가 포함된 최종 문서를 확인하고, 엑셀로 출력 또는 PDF 출력으로 내려받습니다. PDF는 A4 가로 한 장에 맞춰 자동 축소됩니다.
  6. 06
    근무자 서명
    미리보기의 서명하기 버튼을 눌러 화면에 직접 서명하면 해당 직원·해당 월에 서명이 저장되고, 상단에 서명 미완료 인원이 자동으로 집계됩니다.
  7. 07
    근무표 확정
    월 근무표 입력이 끝나면 근무표 확정을 누릅니다. 확정 후에는 이 지사에서 직접 수정할 수 없고, 수정 요청 버튼으로 변경 사유를 적어 관리자에게 보내야 합니다.
  8. 08
    근로시간 검증시트
    검증 시작일을 지정하고 근로시간 검증시트를 누르면, 91일(13주) 단위로 주64시간·분기평균52시간 초과 여부를 자동 점검하고 ERP 업로드용 양식까지 함께 생성합니다.

관리자

  1. 01
    관리자 로그인
    로그인 화면에서 관리자로 로그인을 체크하고 관리자 비밀번호를 입력하면 전체 지사·전체 메뉴에 접근합니다.
  2. 02
    수정 요청 처리
    운영 알림 · 자동검증 탭 ③번에서 지사가 보낸 수정 요청을 확인하고, 필요 시 확정을 취소해 직접 수정한 뒤 처리완료로 표시를 누릅니다.
  3. 03
    비밀번호 관리
    관리자 설정 탭에서 지사별·관리자 비밀번호는 물론 구역·사번 단위 비밀번호까지 코드 수정 없이 바꾸거나 기본값으로 되돌립니다.
  4. 04
    지사·구역·백업 관리
    같은 탭에서 지사 추가/삭제, 경비지도사 정보 수정, 구역/호수별 직원 배정, 전체 데이터 백업(JSON) 다운로드와 복원을 수행합니다.
  5. 05
    대시보드 · 전사 초과근무 현황
    기준일 하루의 지사별 주·야·숙 인원 분포와 구역 공백, 기준월 한 달간 주64h·분기평균52h 초과 직원을 전체 지사에서 한 번에 확인합니다.

  • GitHub Pages로 접속 가능한 데모
P11~2개월

내부 표준화 · 소규모 파일럿

  • 자동 백업 · 복구 절차 수립

P22~3개월

백엔드 전환

브라우저 저장 방식을 벗어나 여러 지사가 동시에 안전하게 쓸 수 있는 구조로.
  • 서버 + 데이터베이스 구축
  • 계정별 로그인(해시 비밀번호), 지사/본사 권한 체계
  • 동시 편집 충돌 처리, 서버 측 감사로그
완료 조건 — 두 지사가 동시에 접속해도 데이터가 깨지지 않음을 부하테스트로 확인.
P33~4개월

전사 확산 — 1,000명 규모

조직 전체로 넓혀도 성능·운영이 버티는지 확인.
  • 전 지사 데이터 이관, 성능·부하 테스트
  • 모바일 화면 최적화 (현장 서명 대응)
  • 알림 연동(문자·카카오톡), 자동화 테스트 도입
완료 조건 — 40개 지사·1,000명 데이터에서 응답속도·정확도가 파일럿과 동일.
P44~6개월

상품화

한 조직 전용 도구에서, 여러 고객사에 팔 수 있는 소프트웨어로.
  • 멀티테넌시 (고객사별 데이터 완전 격리)
  • 구독·과금 모델, 관리자 콘솔
  • 개인정보 보호법·보안 인증 대응 검토
완료 조건 — 외부 고객사 1곳을 대상으로 유상 파일럿 계약 체결.

리스크와 전제

위 로드맵을 승인하기 전에 경영진이 알아야 할 현재 상태의 한계.

높음
현재 저장소가 Public 상태
배치현장 주소·연락처 등이 마스킹 없이 공개 저장소에 올라가 있습니다. 실사용 데이터를 넣기 전 반드시 Private 전환이 선행되어야 합니다.
높음
로그인은 진짜 보안이 아님
서버가 없는 정적 페이지 특성상 비밀번호가 소스에서 드러날 수 있습니다. 지금은 오조작 방지용 접근 제한이며, P2에서 서버 기반 인증으로 대체되어야 합니다.
중간
자동화 테스트 부재
회귀 버그를 코드 리뷰에 의존해 잡고 있습니다(실제로 이번 개발 중 한 차례 발견·수정). 전사 적용 전 최소한의 테스트 체계가 필요합니다.
중간
동시 편집 충돌 미처리
같은 지사를 두 사람이 동시에 수정하면 나중에 저장한 쪽이 덮어씁니다. P2의 서버 전환 전까지는 지사당 담당자 1명 운영을 권장합니다.
본 문서의 기대효과 수치는 예시 가정에 기반한 추정치이며, 실제 조직의 인건비·소요시간 데이터로 재산정이 필요합니다. 로드맵 기간과 투입 규모는 참고치입니다.
